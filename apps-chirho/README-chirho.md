## Remote contract

Base: https://hinneh.us/ (legacy https://hinneh.bible.systems/ remains available). HTTPS only; permit the exact trusted origin for all relative resources and reject other hosts, traversal and unexpected schemes. Do not ship credentials. Fetch only a selected book/chapter, validate chapter hashes and content binding, keep memory/disk caches bounded and cancellable, and cancel stale passage requests/playback. Native network APIs need no browser CORS exception. Remote text is exact source Unicode, never normalized. Hebrew uses RTL, Greek LTR; icons and morphology stay attached to their own words. Unsupported fields/meanings/audio stay explicitly unavailable.

- GPT will provide /library-chirho/books-chirho.json, a small versioned bootstrap list derived from config-chirho/bible-chirho/books-chirho.json. Until it is live, read that local registry to develop a bundled fallback list of book identities only, not the corpus.
- /content-chirho/<slug>/manifest-chirho.json has book_id_chirho, label_chirho, language_chirho and chapters_chirho with number_chirho, verse_count_chirho, path_chirho, sha256_chirho and optional explicit verse_numbers_chirho. Never infer verse presence from array offset or the count alone.
- A chapter has verses_chirho. See src/lib/bible-chirho/content-client-chirho.ts and domain-chirho/{lesson-chirho,greek-chirho}.ts for the real shape. Preserve canonical text, exact token ids/spans, qere, augmented Hebrew lemmas and exact Greek lexical forms. The web's teaching cues are documented in domain-chirho/{cues-chirho,greek-cues-chirho,verb-forms-chirho}.ts.
- /media-chirho/<slug>/summary-chirho.json lists only chapters with media. Fetch its listed chapter path and verify sha256, retry the summary once after a mismatch. Chapter scenes_chirho, icons_chirho and lemma_icons_chirho carry root-relative assets and review states. Use the contextual record first, then the full-lemma default; do not invent reviewed senses or double borders. Follow src/lib/reader-chirho/navigation-chirho/media-client-chirho.ts.
- /audio-chirho/<slug>/chapter-NN-chirho.json carries content_path_chirho and content_sha256_chirho plus clips_chirho. Bind it to the exact content chapter. A clip identifies lesson/token/text/canonical SHA, pronunciation/recipe, root-relative asset_path_chirho, sha256, bytes, duration and joining windows. Single-word playback plays the complete MP3 to its natural end; trim windows are only for assembled readings. Stream with native playback. Keep existing natural readings where available; read the web audio client for rendition selection. No synthesis or device-voice downgrade is required for this first native vertical.
- /glosses-chirho/es-chirho/manifest-chirho.json and selected-chapter layers are optional, hash/content-bound Spanish meanings. The interface can start EN/ES. Never fill an unavailable approved layer with machine text.

Build a coherent native reading vertical: book/chapter/verse controls, local-day Proverbs default with explicit selection taking precedence, original text with grammar cues, word pictures, tap-to-inspect meanings/morphology/source notes, individual-word audio, previous/next, and the verse scene when available. Keep original-language text when any optional media fails. Show required source attributions and honest pending/AI audio-art labels. Use large accessible text, native focus/VoiceOver/TalkBack, responsive layouts and cancellation/retry states. Keep image reports in the existing trusted website flow; do not weaken the server's Origin/Turnstile checks for an app.

Read AGENTS.md and the real pinned data before implementing. Own only the assigned subdirectory and report exact paths, executed build/tests, any missing toolchain, and unresolved decisions to GPT through Metropoliluya. No parallel website/data/art edits.
