# Hinneh reusable media library

This deterministic catalogue describes public release 751f6aceb3b37dbf7d83879246c38a141c9ed660d47c14503158399bdadd593a. Media bytes stay on R2 and are served through https://hinneh.us/. This export downloads no media. Check every shard against manifest-chirho.json, then download a chosen asset and verify its declared SHA-256 and byte count. Public availability is not an immutable availability promise; keep a verified copy when archiving.

The icons-chirho records keep exact Hebrew lemma plus augment identities and exact Greek lemma plus lexical-form identities. Never normalize Greek strings or treat a Strong number alone as a complete identity. Pictures can have several senses. A lemma_default is a general memory aid, not a contextual sense judgment. Source lesson/token fields identify the reviewed example; repeated chapter defaults are deduplicated.

The word-audio-chirho records distinguish the published IPA or synthesis-input digest, language, pronunciation profile, voice, provider and model. Their catalogue_synthesis_key_chirho describes published fields, not undisclosed provider settings or the private production cache. A recording id also includes the MP3 hash, so different bytes are never merged. Each recording keeps exact source-text and recipe aliases; words with different cantillation spelling can reuse the same sound. Audio is not keyed by lemma: inflection, qere, stress and pronunciation can change the recording. The audio-occurrences-chirho shards bind each verse to its canonical SHA and catalogue/content paths; words_chirho contains [token id, recording id, zero-based alias index] triples. Source-catalogues-chirho supplies exact published input hashes and URLs. Metadata and its Unicode are preserved without normalization. Existing natural verse recordings are retained by Hinneh but excluded from this word library.

The scenes-chirho records preserve standard and representation_reduced variants. Asset facts, download URLs, dimensions or durations, unique counts and uncompressed download byte totals are in assets-chirho and the root manifest. Metadata shards are each below 2 MiB. The shard directories are bounded asset-like collections. GitHub Release archives can group icons, audio and scenes separately; this export does not upload archives or commit binaries. Archive sizes require measurement after packaging.
